§Folio II · Tabula I

The dual-mind architecture

The patron and architect agree on the work. Castor carries the brief into the local workshop and returns a compact result for independent review.

The Architect · Gemini

Read the repository, clarify the design, write spec.md, review the real git diff, and run the acceptance checks independently.

The Artisan · local Codex CLI

Implement the brief, verify the change in the assigned checkout, and deliver the six-field JSON report. Resume the same session when review calls for rework.

✦Folio III · Tabula II

The zero-polling cycle

Antigravity runs dispatch and resume in the background. End the turn after dispatch, or work on something unrelated until the result arrives.

  1. Draft the spec

    Gemini reads the repository and writes a six-part Markdown brief covering objective, context, detailed requirements, constraints, verification, and acceptance.

  2. Dispatch in background

    Call codex_dispatch with background: "always". Set use_worktree: true to create a managed checkout, and share the task ID and branch.

  3. Yield at zero tokens

    Gemini yields while Codex works autonomously. Skip polling loops, polling timers, and sleeps.

  4. Wake on completion

    Antigravity wakes Gemini on tool return with the JSON report and git.diff_stat.

  5. Review independently

    Inspect the diff and run the checks. Merge accepted changes before codex_cleanup_worktree, or send specific feedback through codex_resume to preserve session memory.

§Folio IV · Tabula III

Six MCP instruments

All six tools load eagerly (eager: true), with async background mode configured in Antigravity. Select a tool to inspect its parameters, call payload, and returned result.

codex_dispatchbackground: always codex_resumebackground: always codex_statusbackground: off codex_cancelbackground: off codex_cleanup_worktreebackground: off codex_monitorbackground: off

codex_dispatch

background: always

Start a new implementation from a self-contained Markdown spec. By default Codex edits the active checkout.

ParameterUse
workdirRequired absolute path to the target directory.
spec / spec_fileProvide Markdown text or the absolute path to a spec file.
task_idOptional unique ID. The server generates one when omitted.
use_worktree / base_refCreate a managed worktree and select its base. Defaults: false and HEAD.
model / reasoning_effortOptional Codex model and reasoning overrides.
extra_writable_dirsOptional paths passed through via --add-dir.
Example call
{
  "name": "codex_dispatch",
  "arguments": {
    "workdir": "/home/dev/project",
    "spec_file": "/home/dev/specs/task-a.md",
    "task_id": "task-a",
    "use_worktree": true
  }
}
Return excerpt
{
  "task_id": "task-a",
  "round": 1,
  "status": "completed",
  "report": {
    "status": "completed",
    "summary": "Documented the CLI.",
    "files_changed": [
      "README.md"
    ],
    "commands_run": [
      "git diff --check (passed)"
    ],
    "tests_summary": "Diff whitespace check passed.",
    "open_issues": []
  },
  "git": {
    "branch": "codex/task-a",
    "diff_stat": "README.md | 2 ++"
  }
}

Set use_worktree: true whenever two or more artisans edit the same repository.

codex_resume

background: always

Continue a previous Codex session with concrete review feedback in its work directory.

ParameterUse
task_idReuse the session and working directory from an earlier task.
session_id / workdirSupply both when resuming without a task ID.
feedback / feedback_fileProvide actionable feedback or the path to a Markdown feedback file.
model / reasoning_effortOptional Codex model and reasoning overrides.
Example call
{
  "name": "codex_resume",
  "arguments": {
    "task_id": "task-a",
    "feedback": "README.md: document the config path."
  }
}
Return excerpt
{
  "task_id": "task-a",
  "round": 2,
  "status": "completed",
  "git": {
    "branch": "codex/task-a",
    "diff_stat": "README.md | 3 +++"
  }
}

Cite the file and line, include failing output, and say what should happen.

codex_status

background: off

Inspect a single task or list recent tasks. Use on explicit request or during post-mortem debugging.

ParameterUse
task_idInspect one task, including recent events and stderr tail.
limitLimit the recent task list when task_id is omitted. Default: 20.
Example call
{
  "name": "codex_status",
  "arguments": {
    "task_id": "task-a"
  }
}
Return excerpt
{
  "task_id": "task-a",
  "status": "running",
  "alive": true,
  "round": 1,
  "last_event": "turn.started"
}

Take one snapshot. The completion result arrives on its own.

codex_cancel

background: off

Stop a running Codex process group. The server sends SIGTERM and escalates to SIGKILL if needed.

ParameterUse
task_idRequired ID of the running task.
Example call
{
  "name": "codex_cancel",
  "arguments": {
    "task_id": "task-b"
  }
}
Return excerpt
{
  "task_id": "task-b",
  "cancelled": true,
  "message": "Terminated running Codex process."
}

The process stops. Any changes it made stay in the checkout.

codex_cleanup_worktree

background: off

Remove a managed worktree after reviewing and merging its changes or deciding to discard them.

ParameterUse
task_idRequired ID of the task that owns the managed worktree.
delete_branchAlso remove the task’s branch. Default: false.
forceForce worktree removal and branch deletion if requested. Can discard work. Default: false.
Example call
{
  "name": "codex_cleanup_worktree",
  "arguments": {
    "task_id": "task-a",
    "delete_branch": true
  }
}
Return excerpt
{
  "task_id": "task-a",
  "cleaned": true,
  "branch_deleted": true
}

Merge accepted changes before removing the worktree.

codex_monitor

background: off

Open a side panel or full-page view in Antigravity App, or get a snapshot of running and recent tasks with their effective model, reasoning effort, elapsed time, and recent activity. For each setting, the live rollout’s turn_context takes precedence, followed by an explicit codex_dispatch or codex_resume override, the previous round, then project and user .codex/config.toml defaults. The monitor flags settings that differ from the configured defaults.

ParameterUse
task_idOptional ID of the task to select.
limitOptional cap on the number of tasks listed. Use a non-negative integer. Default is 20.
Example call
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "codex_monitor",
    "arguments": {"task_id": "task-a", "limit": 5}
  }
}
Return excerpt
{
  "structuredContent": {
    "active_count": 1,
    "selected_task": {
      "task_id": "task-a",
      "status": "running",
      "effective_model": "gpt-6.2-sol",
      "effective_reasoning_effort": "high",
      "model_source": "runtime_rollout",
      "config_reasoning_effort": "xhigh",
      "elapsed_seconds": 42.3,
      "current_activity": "▶ python3 -m unittest"
    }
  }
}

Opens the live side-panel monitor in Antigravity App. While tasks are active, it refreshes every 2s via tools/call at zero LLM tokens. When idle, it refreshes every 8s.

❧Folio VI · Tabula V

Quickstart inscription

Requires Python 3.9+, Git, a configured local Codex CLI, and Antigravity. Run these commands from your terminal.

  1. Install Codex Castor

    Clone the repository and run the installer. Add --install-statusline to show active tasks below Antigravity CLI’s built-in status bar. Reload Antigravity afterward.

    git clone https://github.com/JAY201368/codex-castor.git && cd codex-castor && ./scripts/install.sh

  2. Verify the installation

    From the clone, check the installed configuration and run an MCP stdio handshake.

    python3 scripts/doctor.py

  3. Uninstall when needed

    Remove the installer-managed integration. Add --purge-state if you also want to remove saved Castor state.

    python3 scripts/install.py --uninstall

Full permissions & independent review

Dispatch and resume both pass --dangerously-bypass-approvals-and-sandbox and --dangerously-bypass-hook-trust for unattended execution. Use Codex Castor in trusted local developer workspaces. Git worktrees separate checkouts while Codex retains your local user permissions. Inspect the diff and run checks independently before merging.
